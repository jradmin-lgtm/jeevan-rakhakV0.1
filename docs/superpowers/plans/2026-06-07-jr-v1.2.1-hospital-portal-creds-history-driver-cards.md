## Goal
1. **Security fix (do first):** `GET /api/v1/hospitals` leaks `portal_password_hash` to every authenticated user/driver (it `select()`s all columns). Lock it to safe columns.
2. **Credentials on the hospitals dashboard:** list each hospital with Login ID (= hospital name slug) + **viewable password** + Reset + Delete + Enable, admin-gated.
3. **Portal history:** the hospital portal shows ALL rides to that hospital (active + completed + cancelled), not just active.
4. **Driver cards:** clickable driver name → a driver detail view (profile + stats + rides) **scoped to this hospital only** (never other clients' ride data), realtime — like the admin driver page.
5. **One locked booking ID + ride cards:** the human `#displayId` is the single identifier shown identically on EVERY surface (hospital queue, history, driver card, ride card, admin, apps). It's set once at booking creation and is immutable — including across a CR#2 re-dispatch (same booking row → same `displayId`), so one ride = one id forever. Clicking any ride → a live **ride card** (`/h/<id>`) showing status + A/B/C, updating in realtime like the admin booking detail.
6. **Feedback / issue-ticket system:** the hospital can **raise a ticket** (feedback or concern about a DRIVER, a RIDE, or GENERAL) from the portal — incl. a contextual "Raise concern" on the driver card + ride card. Tickets land in the admin **Help & Support** section as issue tickets; admin can **Mark resolved**; a **live open-ticket counter** shows in the admin nav + dashboard analytics. Driver card stays **read-only** (no KYC enable/disable — that's admin-only; the portal only views verified + ride statuses).

## Security model (unchanged boundary)
- Login still verifies against scrypt `portalPasswordHash`. A new **admin-only** `portalPasswordPlain` is the recoverable copy for the dashboard display.
- `portalPasswordPlain`/`portalPasswordHash`/`portalUsername` must NEVER be returned by: the public `GET /api/v1/hospitals`, or any `/hospital/*` (hospital-JWT) endpoint. Only `GET /api/v1/admin/hospitals` (admin-key gated) returns the plain (for display) — and must NOT return the hash.
- Every `/hospital/*` query stays scoped to `req.user.hospitalId` (claim only). The new driver-card endpoint scopes the driver's rides/stats to rides where `destHospitalId = hid` — never the driver's activity at other hospitals.
