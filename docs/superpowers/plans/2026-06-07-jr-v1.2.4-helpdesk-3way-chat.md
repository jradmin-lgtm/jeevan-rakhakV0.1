**Date:** 2026-06-07 · **Builds on:** v1.2.3 (`b623c5c`, live) · **APP CHANGES → new APKs** (versionCode 31→32) · branch `prod` · additive, fail-loud DDL, zero regression.

## Goal — turn Help & Support into a real-world helpdesk
1. **3 sources** of tickets into the admin: **Hospital** (live) + **Driver app** + **User app**.
2. **Openable ticket card** (admin + portal) with a **to-and-fro chat thread** (both sides post).
3. **Priority + Severity** flags (admin triage); shown + filterable.
4. **No close without a reply** + **capture the closer's name** (resolved_by).
5. **Filters** on the admin list: source · priority · severity · category · status · **date range**.
6. Apps (driver+user): Help & Support screen — **raise + view + chat** (two-way).

## Data model (additive)
`support_tickets` += `source text NOT NULL DEFAULT 'HOSPITAL'` ('HOSPITAL'|'DRIVER'|'USER'), `priority text NOT NULL DEFAULT 'NORMAL'` ('LOW'|'NORMAL'|'HIGH'|'URGENT'), `severity text NOT NULL DEFAULT 'MEDIUM'` ('LOW'|'MEDIUM'|'HIGH'|'CRITICAL'), `resolved_by text`, `raiser_user_id uuid`, `raiser_driver_id uuid`. New `support_ticket_messages` (id, ticket_id FK, author_role 'ADMIN'|'HOSPITAL'|'DRIVER'|'USER', author_name text, body text, created_at). The raiser's first message is the ticket `message` (kept) + ALSO seeded as the first thread row so the card reads as one conversation.

## RBAC
Each raiser sees ONLY their own tickets + threads: hospital `hospital_id=hid`, driver `raiser_driver_id=sub`, user `raiser_user_id=sub`. Admin (x-admin-key) sees all. Posting a message requires ownership (or admin). Admin posts `author_role='ADMIN'`.
